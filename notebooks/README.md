# NetFlow SQL notebooks

[A missing template is not zero traffic](01_missing_template_is_not_zero_traffic.ipynb) decodes synthetic v5/v9 export payloads, keeps missing-template diagnostics visible, and compares available byte counters with a complete reference. The parameter experiment withholds only the v9 template from the selected scan.

## Run from this directory

Install [uv](https://docs.astral.sh/uv/) and Python 3.13 or 3.14. Network access is needed on first use for dependencies, published Haybarn extensions and the pinned native worker release. The notebook can run from a copy of this entire directory, without the worker source tree or a Rust build.

```bash
uv sync --frozen
uv run --frozen python execute.py
```

The visible SQL uses `github-auto://Query-farm/vgi-netflow@v0.4.0`. Haybarn/VGI downloads the platform release and verifies its SHA-256 sidecar. The notebook environment is separately locked to Haybarn 2.0.0rc11. The INET extension supplies address types. To upgrade the worker pin, change the literal release tag, then repeat the default, experiment and invariant checks.

For interactive use, register this interpreter and select it in Jupyter:

```bash
uv run --frozen python -m ipykernel install --user --name vgi-netflow-notebooks --display-name 'Python (vgi-netflow notebooks)'
```

Restart and run all after editing the visible parameter. Python setup, plotting and cleanup are folded; connection SQL, domain transformations, charts and interpretations remain visible. The runner uses a temporary kernel and this directory as cwd, saves only after success, requires a separate destination for overrides, and rejects unknown parameter names or an output destination equal to the source directory.

## Focused experiment

```bash
uv run --frozen python execute.py --parameters '{"INCLUDE_TEMPLATE":false}' --output-dir validation/without-template
```

The same two data datagrams remain selected; only the separate v9 template is withheld. The complete reference scan always retains it. Each decode scan has its own template state. The worker's `templates()` introspection projection can contain previously learned layouts, so the notebook does not mistake that projection for this scan's context. No live traffic or socket collector is used.

The three `.dat` files are unchanged synthetic golden fixtures generated by `crates/netflow-core/src/fixtures.rs` in the repository. Their embedded export time, 2023-11-14 22:13:20 UTC, is invented, not an observation/capture clock. [Provenance](fixtures/provenance.json) records hashes, sizes and source revision. Exporter labels are notebook inputs. Addresses and port numbers do not establish real traffic or application identities.

## Validation and interpretation

The default and detached template-withheld experiment passed. Known selected bytes changed from 2,000 to 1,200; decoded flow rows changed from three to two, with one missing-template diagnostic and the v5 control unchanged. Repository gates passed: 32 Rust tests, 103 stdio / 111 HTTP / 103 Unix SQL assertions, release build, Clippy, formatting and docs. Executing metadata lint scored 100/100, L2 behavioral, with zero findings.

Eleven SQL invariants check input validity, unchanged data selection, the v5 control, complete-reference decoding, null diagnostic counters, per-scan v9 template dependence, and aggregate reconciliation. Output diagnostic rows are not flow-record or packet counts. One unresolved Data Set may contain an unknown number of records; unavailable traffic counters stay NULL rather than becoming zero. A smaller known sum is not evidence of less traffic. The reference allows an exact comparison only for these deliberately complete synthetic inputs.

Default outputs are saved inside the notebook. Separate experiment notebooks, logs and extracted review charts are generated under ignored `validation/` directories. The runner copies relative assets, fixtures and runtime companions alongside experiment copies. [STANDARD.md](STANDARD.md) records presentation conventions.
